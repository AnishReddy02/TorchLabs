The solution

A control plane for the physical lab.

A small Linux Bench Node stays connected to each asset. Engineers reserve hardware, deploy existing software bundles, run existing scripts, stream logs, and keep results—from anywhere.

BENCH
Why now

Robotics teams are becoming software organizations.

01

More software per machine

Autonomy, perception, controls, and embedded compute increase release frequency and integration risk.

02

Hardware remains scarce

Real assets are expensive, shared, geographically constrained, and impossible to fully virtualize.

03

Developer tooling is lagging

Cloud software has mature CI. Physical systems still rely on lab access, chat messages, and bespoke scripts.

Bench brings the operating model of modern CI to the part of the stack that cannot be simulated.

Roadmap

From useful prototype to trusted lab infrastructure.

Now → design partner

Win the core loop

Durable deployments, clear run UX, robust reconnect/interruption semantics, artifacts, installation, and measurable time saved.

Next

Operate a real lab

Multi-asset nodes, health checks, compatibility scheduling, access controls, TLS/mTLS, secrets, and audit exports.

Later

Deep reproducibility

Nix environments, signed workflows, Docker/Systemd executors, release qualification, and hardware-aware orchestration.

Deliberately not next: AI diagnosis, billing complexity, Kubernetes, ROS visualization, CAN decoding, or a plugin marketplace.
